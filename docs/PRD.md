## 1. 产品概述

### 1.1 产品定位

小书匠（XHS Generator）是一款面向内容创作者的**小红书图文一键生成工具**，通过 AI 大模型技术帮助用户快速生成符合小红书平台规范的高质量图文内容，包括封面卡片、帖子标题和正文文案。

**核心价值**：将原本需要数小时的图文创作流程压缩至数十秒，显著降低内容创作门槛。

### 1.2 目标用户

- **小红书内容创作者**：需要高频发布图文笔记的博主
- **品牌运营人员**：需要批量产出平台内容的企业用户
- **健康饮食垂类用户**：食谱、养生、阑尾炎恢复等垂直内容创作者
- **普通用户**：有分享欲望但缺乏设计能力的普通用户

### 1.3 产品目标

- 提供 4 种主流小红书风格模板，覆盖食谱、合集、科普、日记四大内容类型
- 生成内容严格符合小红书图文尺寸规范（1080×1440px，3:4 黄金比例）
- 支持 AI 标题、正文、图文卡片的分模块生成与独立优化
- 通过用户分级（游客/普通用户/管理员）实现合理的使用量管控
- 支持用户自定义 LLM API，满足高频用户的无限使用需求

## 2. 功能需求

### 2.1 整体布局

采用**左右分栏式布局**，左侧为输入控制区，右侧为内容输出区。

| 区域 | 说明 | 尺寸/配置 |
|------|------|-----------|
| 顶部导航栏 | Logo + 用户状态 + 设置入口 | full width，高度固定 |
| 左侧输入区 | 话题输入、补充内容、模板选择、生成按钮 | 宽度 480px，独立滚动 |
| 右侧图文区 | 图文卡片大块展示（左） | flex-1 自适应宽度 |
| 右侧标题区 | 标题列表，右上方 | 宽度 400px |
| 右侧正文区 | 正文内容，右下方 | 宽度 400px |

### 2.2 输入控制区（左侧）

#### 2.2.1 话题输入

- 单行文本框，placeholder：「请输入帖子主题，如：减脂期间的低卡早餐」
- 必填字段，为空时禁用生成按钮

#### 2.2.2 补充内容输入

- 多行文本框，rows=7，可纵向拉伸
- 用于输入原始素材、参考资料等补充内容
- AI 会将其作为素材参考，**提炼重写，不原文照搬**

#### 2.2.3 模板选择

2×2 网格布局，共 4 种模板，点击选中后高亮（brand color #ff4757）：

| 模板ID | 名称 | 主色调 | 适合内容 |
|--------|------|--------|---------|
| template-recipe | 清新食谱风 | #f97316 暖橙 | 食谱、健康料理（3-5张卡片） |
| template-collection | 干货合集风 | #f5e6c8 棕黄 | 知识合集、清单（4-6张卡片） |
| template-science | 科普知识风 | #e8f5e0 浅绿 | 健康科普、营养知识（4-6张卡片） |
| template-diary | 日记分享风 | #f7ede0 暖米色 | 日记、生活记录（4-6张卡片） |

#### 2.2.4 使用量展示

在生成按钮上方展示剩余可用次数 Badge：

- 游客：显示「免费试用 X/3 次」
- 普通用户：显示「免费额度 X/10 次」
- 自定义 API 用户 / 管理员：显示「无限制」
- 次数耗尽后生成按钮变为禁用态

#### 2.2.5 生成按钮

- 按钮文案：「✨ 生成小红书帖子」
- 生成中：Loading 态，文案改为「生成中...」
- 使用量耗尽：禁用，颜色变灰

### 2.3 图文卡片区（CardSection）

#### 2.3.1 卡片渲染

- 使用 **iframe + document.write()** 进行 CSS 隔离渲染
- 卡片原始尺寸 1080px 宽，通过 `CSS transform: scale()` 缩放适配容器
- 使用 `ResizeObserver` 监听容器宽度变化，动态更新缩放比例
- 容器高度 = iframe 实际高度 × 缩放比例

#### 2.3.2 卡片规范

| 属性 | 规范值 |
|------|--------|
| 每张卡片尺寸 | width: 1080px; height: 1440px（固定，不可撑高） |
| 溢出处理 | overflow: hidden（超出内容自动裁切） |
| 容器背景 | background: #e8e8e8 |
| 主标题字号 | 72~88px，bold/900 |
| 分节标题字号 | 44~52px，bold |
| 正文字号 | 30~34px，行高 1.7 |
| 注释标签字号 | 24~26px |
| 内容内边距 | padding 60px 以上 |

#### 2.3.3 操作按钮

- **「优化图文」**：对当前卡片内容进行 AI 二次优化
- **「导出 PNG」**：使用 html2canvas 导出原始 1080px 宽度的高清图片（scale: 2）
- **「版本历史」**：仅登录用户可见，展示历史版本列表，支持一键回退

#### 2.3.4 版本历史（登录用户专属）

- 每次生成或优化时，将旧版本 HTML 推入历史栈（本地 state 存储）
- 版本列表按时间倒序排列，显示「版本 1」「版本 2」等标签
- 点击「回退至此版本」即可恢复，并截断该版本之后的记录

### 2.4 标题区（TitlesSection）

- 展示 5 个 AI 生成的候选标题
- 每个标题采用「可点击选中 + 独立复制按钮」双区域设计
- 点击标题行：高亮选中，背景变色
- 点击复制按钮：复制到剪贴板，按钮显示「✓ 已复制」2 秒后恢复
- **标题公式**：emoji + 诉求词 + 核心词 + 效果承诺，字数 20-25 字
- 底部提供「优化建议」输入框 + 「重新生成标题」按钮

### 2.5 正文区（BodySection）

- 展示 300-500 字的小红书风格正文
- **内容规范**：步骤格式、数值加「约」前缀、使用 ✅💡🔥 等符号、引导互动结尾
- 底部提供「优化建议」输入框 + 「重新生成正文」按钮

### 2.6 历史记录

- 登录用户可在导航栏进入「历史记录」页面
- 展示历史生成的帖子列表（话题、模板、生成时间）
- 点击可查看历史帖子的图文、标题、正文详情

### 2.7 用户系统

#### 2.7.1 注册/登录

- 账号字段类型：**text**（非 email），支持纯用户名登录
- 密码使用 bcryptjs 哈希存储
- 基于 NextAuth.js Credentials Provider + JWT 策略

#### 2.7.2 LLM 设置

- 用户可在设置页面配置自定义 LLM API
- 支持 OpenAI 兼容格式：Base URL + API Key + 模型名称
- 配置后使用次数不限，使用用户自己的 API Key 调用

## 3. 使用量管控规则

| 用户类型 | 识别方式 | 限制次数 | 备注 |
|---------|---------|---------|------|
| 游客（未登录） | IP 地址 | 3 次（总量） | 跨 session 持久化，存 GuestUsage 表 |
| 普通用户（已登录） | userId | 10 次（总量） | 使用内置 DeepSeek API |
| 配置了自定义 API 的用户 | userId + LlmConfig 存在 | 不限制 | 使用用户自己的 API Key |
| 管理员（admin） | username === 'admin' | 不限制 | 系统管理账号 |

次数耗尽后 API 返回 429，前端展示提示，生成按钮置灰。

## 4. AI Prompt 规范

### 4.1 图文卡片 Prompt

- 必须声明每张卡片 `width:1080px; height:1440px; overflow:hidden`（不允许撑高）
- body 布局：`display:flex; flex-direction:column; align-items:center; gap:30px; padding:30px; background:#e8e8e8`
- 明确字号分级规范（主标题 72-88px / 分节标题 44-52px / 正文 30-34px / 注释 24-26px）
- **补充内容只作素材参考，需提炼改写，明确禁止原文复制**
- 输出纯 HTML，不加 markdown 代码块标记

### 4.2 标题 Prompt

- 公式：emoji + 诉求词 + 核心词 + 效果承诺
- 字数控制：20-25 字
- 输出格式：JSON 数组，包含 5 个候选标题

### 4.3 正文 Prompt

- 字数：300-500 字
- 格式：步骤列表，数值加「约」前缀
- 视觉符号：✅💡🔥
- 结尾：引导互动的问句

## 5. 数据模型

| 模型 | 主键 | 关键字段 | 说明 |
|------|------|---------|------|
| User | id (String) | username, password, email | 用户账号，密码 bcrypt 加密 |
| LlmConfig | id (String) | userId, baseUrl, apiKey, model | 用户自定义 LLM 配置，1:1 关系 |

## 6. 技术架构

### 6.1 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端框架 | Next.js 14 App Router | SSR + CSR 混合渲染 |
| UI | Tailwind CSS | brand color #ff4757 |
| ORM | Prisma | 类型安全数据库访问 |
| 数据库 | SQLite | 轻量级文件数据库，适合单机部署 |
| 认证 | NextAuth.js | Credentials Provider + JWT |
| AI | DeepSeek API（默认） | OpenAI 兼容格式，支持用户自定义 |
| 图片导出 | html2canvas | 1080px 原始宽度，scale: 2 高清 |
| 卡片预览 | iframe + CSS transform | CSS 隔离 + ResizeObserver 响应式缩放 |

### 6.2 API 接口

| 接口路径 | Method | 说明 |
|---------|--------|------|
| POST /api/generate | POST | 生成完整帖子（图文+标题+正文） |
| POST /api/generate/optimize-card | POST | 优化图文卡片 |
| POST /api/generate/optimize-body | POST | 优化正文 |
| POST /api/generate/regenerate-titles | POST | 重新生成标题 |
| GET /api/usage | GET | 查询当前用户剩余使用次数 |
| GET /api/history | GET | 获取历史记录列表 |
| GET /api/history/[id] | GET | 获取单条历史记录详情 |
| GET/PUT /api/settings/llm | GET/PUT | 查询/更新 LLM 配置 |
| POST /api/auth/register | POST | 用户注册 |

| 配置项 | 值 |

| Build 配置 | ignoreBuildErrors: true（跳过 TS 类型检查） |

### 7.1 PM2 启动配置注意事项

`ecosystem.config.json` 中 `script` 字段必须指向 Node.js 可执行的 JS 文件路径：

- ✅ **正确**：`node_modules/next/dist/bin/next`
- ❌ **错误**：`node_modules/.bin/next`（这是 shell wrapper，PM2 会当 JS 执行，导致语法错误）

## 8. 非功能需求

### 8.1 性能

- 图文生成响应时间：≤ 15 秒（取决于 LLM API 响应速度）
- 页面首屏加载时间：≤ 3 秒
- 卡片预览缩放响应：实时（ResizeObserver 驱动）

### 8.2 安全

- 用户密码使用 bcryptjs 哈希存储，不保存明文
- API Key 存储在数据库中，仅服务端使用，不暴露给前端
- 游客识别使用 IP 地址，防止无限刷单
- 管理员账号通过 username 字段判断，非角色字段

### 8.3 兼容性

- 支持 Chrome、Safari、Edge 等主流现代浏览器
- 最低分辨率支持：1280px 宽度
- 不要求移动端适配（PC 专属工具）

## 9. 已知问题与未来优化方向

### 9.1 当前限制

- 版本历史仅存于前端 state，刷新页面后丢失（未持久化到数据库）
- SQLite 单文件数据库不支持高并发，适合单机/小规模使用
- 图片导出使用 html2canvas，对复杂 CSS 的支持有限制

### 9.2 后续优化方向

- **版本历史持久化**：将卡片 HTML 历史版本存入数据库
- **会员体系**：付费解锁更多次数或高级模板
- **模板市场**：支持用户自定义上传模板
- **批量生成**：输入多个话题批量产出多套帖子
- **微信/企业微信登录**：降低注册门槛
- **图文编辑器**：在线微调卡片内容（文字/颜色）
- **HTTPS 支持**：配置 SSL 证书
